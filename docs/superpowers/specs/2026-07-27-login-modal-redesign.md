# 登录弹窗 UI 重设计规格

## 目标与用户

登录弹窗服务于准备上传图片、但尚未完成认证的用户。用户需要在不离开当前页面的情况下，通过扫码或手动填写 Bilibili Cookie 完成认证。

本次重设计的核心目标：

- 保留扫码登录和手动填入两种完整登录能力。
- 保留当前清晰的线性 Tabs。
- 恢复旧版弹窗紧凑、直接、窄体的布局特征。
- 在同一视口和状态下，让两个 Tab 的弹窗宽度与高度保持一致。
- 响应式行为遵循首页的移动优先策略，而不是仅设置一个桌面固定尺寸。

## 设计方向

采用“窄体弹窗 + 固定内容舞台”结构。

弹窗由标题区、Tabs 和内容舞台三部分组成。两个 TabsContent 使用相同的响应式高度，内部内容独立排布，因此切换登录方式时外框不发生尺寸跳动。

保留当前线性 Tabs、密码显示按钮、认证反馈和安全提示；移除可见的副标题，将其保留为无障碍描述。手动登录帮助区借鉴旧版的紧凑步骤结构，减少纵向占用。

视觉继续服从项目现有黑白灰主题，不使用首页局部强调色 `#e7c59a`，也不引入新的成功色。

## 信息结构

```text
┌────────────────────────────┐
│            登录         ×  │
│                            │
│    扫码登录      手动填入   │
│  ───────────               │
├────────────────────────────┤
│                            │
│       固定内容舞台          │
│                            │
└────────────────────────────┘
```

### 标题区

- 仅显示“登录”标题。
- “使用二维码扫码登录，或手动填入登录凭证”作为屏幕阅读器描述。
- 关闭按钮保持右上角位置和现有交互。

### Tabs

- 保留 `line` 变体。
- 两个选项等宽：扫码登录、手动填入。
- 图标与标签保持居中。
- 激活状态使用前景色和底部指示线。
- Tab 切换只改变内容，不改变弹窗尺寸。

## 扫码登录布局

扫码页面在固定内容舞台内垂直居中，由二维码区域和状态区域组成：

```text
┌────────────────────────────┐
│                            │
│        ┌──────────┐        │
│        │  二维码   │        │
│        └──────────┘        │
│                            │
│   请使用 B 站 APP 扫码登录   │
│      有效期 3 分钟           │
│                            │
└────────────────────────────┘
```

- 二维码区域保持正方形。
- 加载、已扫描、验证中、过期、错误和成功状态继续使用同一二维码区域。
- 状态文字使用固定高度槽位，避免文案变化造成布局移动。
- 错误文案最多占两行；超长技术信息不直接撑高弹窗。
- 重新生成按钮位于二维码覆盖层内。

## 手动登录布局

手动页面在相同内容舞台内采用上下分区：

```text
┌────────────────────────────┐
│ SESSDATA                   │
│ [••••••••••••••••••  👁]  │
│                            │
│ bili_jct                   │
│ [••••••••••••••••••  👁]  │
│                            │
│ [       验证并登录        ] │
│                            │
├────────────────────────────┤
│ ⓘ 如何获取 Cookie           │
│ 登录 B 站 → 开发者工具 →     │
│ Cookies，复制对应值。        │
└────────────────────────────┘
```

- 保留两个密码输入框和独立的显示/隐藏按钮。
- 输入框标签使用等宽字体，辅助内容使用项目正文体系。
- 表单错误和成功反馈使用预留槽位，不移动按钮位置。
- 验证按钮保持全宽，使用项目的黑白主按钮样式。
- 获取说明压缩为操作路径，不使用当前三段式大块说明。
- 安全提示固定为：“Cookie 等同于登录凭证，请勿分享。”

## 响应式规格

响应式遵循首页的移动优先方式：默认样式服务窄屏，`xs` 断点调整密度，`md` 不再扩大弹窗，只改善展示环境。

### 默认：小于 480px

- 弹窗宽度：`calc(100vw - 40px)`，左右各保留 20px。
- 弹窗内边距：16px。
- 标题字号：约 18px。
- Tabs 高度：约 36px。
- 内容舞台高度：约 290px。
- 二维码尺寸：约 160px。
- 输入框高度：38–40px。
- 表单主要间距：约 12px。
- 获取说明使用紧凑版本。
- 弹窗总高度目标：约 420–440px。

### `xs`：480px 及以上

- 弹窗最大宽度：384px。
- 弹窗内边距：18–20px。
- 标题字号：约 19px。
- Tabs 高度：约 40px。
- 内容舞台高度：约 310px。
- 二维码尺寸：约 176px。
- 输入框高度：40px。
- 表单主要间距：14–16px。
- 弹窗总高度目标：约 450–470px。

### `md`：768px 及以上

- 弹窗继续保持 384px 最大宽度，不随桌面视口扩大。
- 内容尺寸不继续放大。
- 可以保持现有背景遮罩和轻量模糊效果。

### 极小高度与软键盘

- 弹窗最大高度基于 `100dvh`，保留安全边距。
- 正常竖屏下不显示滚动条。
- 高度不足或软键盘打开时，允许整个弹窗纵向滚动。
- 不在二维码区或手动表单内部创建独立滚动容器。
- 当前输入项、错误信息和验证按钮必须可以滚动进入可视区域。

## 视觉规范

沿用 `src/styles/global.css` 中的主题变量：

- 弹窗背景：`popover` / `obsidian`
- 页面背景：`background` / `carbon`
- 边框与分隔线：`border` / `graphite`
- 主文本：`foreground` / `chalk`
- 次级文本：`smoke`
- 输入背景：`input`
- 错误状态：`destructive`
- 主按钮：`primary` 与 `primary-foreground`

不使用：

- `#e7c59a`
- 新增绿色成功色
- 与首页无关的装饰渐变
- 会导致内容高度变化的冗长说明

## 交互与状态

- 默认打开扫码登录。
- 切换 Tab 时当前非活动面板卸载，二维码轮询随之停止。
- 切回扫码登录时重新生成二维码。
- 两种登录方式成功后沿用统一成功回调和延迟关闭行为。
- 关闭弹窗后，下次打开恢复扫码登录。
- 键盘焦点、Tab 顺序和关闭行为沿用 Base UI Dialog/Tabs 的可访问性能力。
- 动画只用于 Tab 指示、状态覆盖层和弹窗进入退出；遵循 `prefers-reduced-motion`。

## 实施边界

本次修改目标：

- `src/components/LoginModal.tsx`
- 必要时调整通用 `Dialog` 的可滚动能力，但不得改变其他弹窗的默认视觉。

保持不变：

- 二维码和 `/myinfo` 接口流程。
- Cookie 写入、恢复和验证逻辑。
- 上传页登录成功后的状态衔接。
- 全局主题色和首页视觉。
- 后端接口和认证协议。

明确不做：

- 登录状态持久化重构。
- 全站 Dialog 重新设计。
- 新增登录方式。
- 修改首页或上传页主体布局。

## 验收标准

- 在 360px、390px、480px、768px 和常见桌面宽度下没有横向溢出。
- 同一视口下切换两个 Tab，弹窗外框宽高不变化。
- 默认状态、加载、扫码、验证、成功、过期和错误状态均不引起外框跳动。
- 手动表单空值、验证中、验证失败和验证成功状态不移动主按钮。
- 手机软键盘打开后可以访问输入框和验证按钮。
- 所有交互可通过键盘完成，焦点状态清晰可见。
- 视觉只使用现有主题体系，不出现 `#e7c59a`。
